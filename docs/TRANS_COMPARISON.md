# 旧TRANSとTransClipの比較・統合判断

調査対象: 旧TRANS commit `25c7856fb20786e9820a18482035f296db1512bb`。指定8モジュールとQwen workerをローカルで読み、GitHub blobと一致することを確認。旧ツリーは読み取り専用。現TransClipの開始時テストは232件成功。

|対象機能|分類|判断と採用範囲|動作の証拠・限界|
|---|---|---|---|
|Qwen Base / `qwen3_tts.py`|両方を組み合わせる必要がある|旧workerの明示的VoiceDesign→参考→Baseという流れを再利用。現行のローカル限定ロード、完全な生成設定/ハッシュ、token上限検出、話者別条件付けキャッシュを維持する。|現行PresetとBaseは各3発話の実モデル生成済み。Baseの新規参考は人手承認済み。生成後の日本語の正しさはユーザー確認済み、全文一致・声質は確認待ち。旧コードの存在は今回の環境での正常動作を証明しない。|
|参考生成 / `qwen_worker.py`|旧TRANSから再利用できる|VoiceDesignの生成呼び出しを現行バックエンド契約へ適合し、seed・revision・指示・正確な入力text・WAV実測・ハッシュを保存する独立CLIを追加。生成直後の自動Cloneは採用しない。|新しい日本語参考12.32秒・英語参考12.48秒を実生成。日本語はユーザーの試聴・再利用承認済み、英語は再利用許可済み、発声内容・品質は未確認。|
|参考選択 / `voice_reference.py`|現在のTransClipの方が優れている|既存Phase 4の重複除外・不確実性・UNKNOWN保持と、Phase 7の許可/品質レビューを維持。旧コードの参考不足時の暗黙fallback、最大時間による切断、単純連結は移植しない。|現行自動テスト・旧コード読解。人物への正解ラベルは未確認。|
|声質QA / `voice_qa.py`|両方を組み合わせる必要がある|参考対生成・文章間のEmbedding比較とF0を併記する考え方を再利用。既存OfflinePyannote/DSPを利用し、少数標本から合格閾値を作らない。|旧実装は他話者がない場合のmax/min空集合に注意。1人でも使え、スコアで自動承認しない構成へ適合する。|
|配置 / `sync_group.py`|旧TRANSから再利用できる|実測長と前発話の終端を用いる考え方を、同一話者内の小幅な遅延に限定して採用。発話波形の切断/倍速は行わない。|合成fixtureと実Clone WAVのMixerで検証し、0.24秒の衝突を0.28秒の配置遅延で解消。開発動画の5組は未解決。旧実装の速度変更の音質は未検証なので不採用。|
|時間計画 / `timing_planner.py`|両方を組み合わせる必要がある|計画とレンダリングを分け、収まらない区間をrepair/reviewとして残す方針を採用。現Feedbackの実測値とMixerの検証を利用する。|大規模なsync segment救済/複数話者をまたぐ移動は別工程。自然な同時発話を優先する。|
|修復 / `repair_attempt.py`|移植する必要がない（今回）|約2300行の状態機械は丸ごと取り込まない。現行候補JSON・意味保持チェック・再評価を維持。未解決の不足時間を記録し、候補生成/実測の循環の拡張は後工程。|旧コードの自動acceptを現行レビュー完了に置換しない。|
|生成管理 / `tts_synthesis.py`|現在のTransClipの方が優れている（今回の範囲）|現行の非破壊アトミック公開、receipt照合、許可再確認、途中再開を維持。旧コードのworkerやGUI前提の大きなサービスは重複移植しない。|現行232テストと実Presetキャッシュ再利用の検証。旧サービス全体の実行は行っていない。|
|自然化 / `localization.py`|移植する必要がない|日英Language Engineに読み辞書、候補評価、意味保持がある。旧コードの特定インタビュー語句の置換は汎用の正解と扱わない。|翻訳/発音の品質は実データ・試聴で評価。|
|GUI / 自動fallback / atempo|移植する必要がない|CLI中心を維持。UNKNOWNへの補完、無条件の参考利用、音声切断、未検証の速度変更を導入しない。|ユーザー指定による対象外。|
